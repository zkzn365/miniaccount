# mini-account

面向中国小微企业的本地记账软件。**Go + Wails v2 + SQLite + Vue 3 / shadcn-vue**。

> 独立实现，不含任何来自 Frappe Books 的代码 —— 见 [`PROVENANCE.md`](./PROVENANCE.md)。
> 以 [MIT 许可](./LICENSE)发布。
>
> 下文引用的「设计文档」指开发时的需求与设计笔记，**不在本仓库内**，
> 因此按《文档名》§小节 的形式引用，不做成链接。

## 当前进度

**建账 → 记账 → 银行流水导入 → 工资 → 发票报销 → 出报表 → 期末结转 → 导出 → 备份 → AI 辅助记账，
全链路已跑通，有可执行程序。**

```bash
cd mini-account
. ./env.sh                        # 重定向 Go 构建缓存（受限环境必需）
go build -o miniaccount ./cmd/miniaccount

./miniaccount demo --db demo.db   # 生成一个演示账套，立刻能看到真实报表
./miniaccount bs     --db demo.db # 资产负债表
./miniaccount pl     --db demo.db --period 2025-03 --ytd
./miniaccount cashflow --db demo.db --period 2025-03
./miniaccount close  --db demo.db --period 2025-03 --preview --by 王主管
./miniaccount backup --db demo.db --out demo.mabak

# 银行流水：导入 → 匹配 → 生成凭证
./miniaccount bank import --db demo.db --file 对账单.csv --by 李会计
./miniaccount bank match  --db demo.db
./miniaccount bank rules  --db demo.db --add --name 房租 --match 房租 --counter 560210 --dept 1
./miniaccount bank post   --db demo.db --all --by 王主管
```

### 桌面版（Wails v2 + Vue3）

```bash
cd mini-account && . ./env.sh
cd desktop && wails build          # 产物在 desktop/build/bin/
```

界面用 Vue3 + Vite + Tailwind v4，组件遵循 **shadcn-vue** 的令牌与变体约定
（`--background` / `--primary` / `--muted` … 同名同义，社区主题可直接套用），
Headless 层用 shadcn-vue 的底层库 reka-ui。

已有页面：首页概览、**凭证录入与列表**（草稿 → 记账 → 红字冲销）、
**发票**（进销项 / 一键生成凭证 / 可抵扣税额自动判定）、
**报销**（草稿 → 审批 → 记账的完整流转）、
**银行流水**（导入 → 三层匹配 → **点单元格就地指定对方科目**（需辅助核算时自动转弹窗）
→ 批量生成凭证 → 规则管理）、
**工资**（员工档案 / 工资单 / 个税参数）、
**固定资产与费用摊销**（卡片 / 计提预览 / 每期计提）、账期管理（体检 / 结账 / 反结账）、
报表（5 张，统一下钻，可**打印 / 另存 PDF**、可**导出 Excel**）、
**账龄分析**（按往来单位 × 科目，先进先出法核销 + 30/60/90/180/365 天分桶）、
**增值税**（查适用税率、判进项能否抵扣、查看带生效期的税率政策表）、
**对账单**（发给客户/供应商核对盖章，可打印 / 复制文本）、
**银行余额调节**（账面 vs 对账单，四类未达账项逐笔列出，
期初不一致时直接点明差额来源）、
**多栏式明细账**（按下级科目横向展开：管理费用各项花销、
应交增值税借方 6 栏 + 贷方 4 栏的专用格式）、
**凭证汇总表**（按凭证字/日期/科目三个角度汇总，三段合计必须相等）、
明细账 / **日记账**（现金、银行存款，带「对方科目」一列）、
AI 记账助手、**设置**（账套信息 / 备份与恢复 / 附件审计 / AI 配置）、
建账向导（可一键**生成演示账套**先看效果）。深色模式跟随系统。

凭证支持**附件**：按 sha256 内容寻址存放，同一份文件挂到多张凭证上只占一份空间；
设置页给出「已记账凭证 / 附有单据 / 缺附件 / 孤儿文件」四个数字。

前端产物用 `//go:embed` 编进二进制 —— 用户拿到的是**一个可执行文件**，
不需要额外的 web 服务器或运行时。

### 已实现的能力

- **建账**：内嵌 190 个《小企业会计准则》科目（66 官方 + 124 实务明细），
  迁移与种子写入均幂等
- **凭证**：草稿 → 过账 → 作废；凭证字号按「期间 + 凭证字」分配，
  唯一索引兜底；断号/重号检查
- **过账只在账期结算时发生**：凭证录完一律先落草稿（不占号、不进总账），
  点结账时先按业务日期把本期草稿全部过账（自动分配凭证号），
  再结转损益、关期间 —— 三步同一个事务，中间失败整批回滚。
  唯一的例外是红字冲销与反结账：它们的全部意义就是让总账上已有的
  凭证归零，留成草稿等于什么都没做
- **过账**：一次过账 = 一个事务（分配字号、写凭证、写总账、改状态）
- **红字冲销**：生成有独立编号的真实红字凭证，原凭证与红字凭证都在账上
- **账簿取数**：总账余额、明细账（可按科目前缀，如「其他应付款—股东」）、试算平衡
- **固定资产折旧**：平均年限法（直线法），月折旧额 =（原值 − 预计净残值）÷ 使用月数，
  最后一期兜尾差保证累计恰好等于应提总额。**当月增加当月不提、次月起提**，
  处置当月照提、次月起停（准则第 4 号第十四条）。按税法五类给出最低折旧年限，
  填短了只警告不拦（会计可以短提，只是要做纳税调整）
- **费用摊销**：长期待摊费用在受益期内平均摊销，**受益期从当月起算，当月就摊第一期**
  （与固定资产的次月不同，不是笔误）。同样最后一期兜尾差
- **折旧与摊销的计提**：按期逐条落记录，`UNIQUE(资产, 年, 月)` 挡住重复计提；
  漏提不报错，所以计提预览会逐条标出**上一期还有几条没提**。
  生成的凭证是**草稿**，与手工凭证、工资凭证走同一条路，到账期结算才过账
- **期间管理**：顺序结账、逆序反结账；过账以数据库中的期间状态为准
- **财务报表**：资产负债表（53 行，含官方 8 条勾稽关系校验）、利润表（32 行，本月数/本年累计数两栏）
- **账簿**：科目余额表（六栏式）、往来单位余额表、明细账（支持按科目前缀，如「其他应付款—股东」）
- **中国报表特有的取数**：`@analyze(1122,2203,debit)` 按明细余额方向拆分、
  `@L(n)` 行引用、备抵科目取正、未结转损益自动计入未分配利润
- **建账**：一次事务内完成「账套信息 + 190 科目 + 12×N 个会计期间」，任何一步失败整体回滚
- **结账前体检**：6 项检查（试算平衡、待过账草稿、凭证字号连续、资产负债表勾稽、
  现金负余额、往来方向异常），区分阻断项与警告项。草稿不再是「问题」——
  它是正常状态，体检只报出结账时会过账几张，让用户在预览里先看见
- **备份**：`.mabak` = zip（manifest + `VACUUM INTO` 快照 + 附件），
  恢复前逐个校验附件 sha256，原账套暂存而非删除
- **Excel 导出**：金额写数值（可在 Excel 里直接求和）、负数用括号、
  冻结表头、勾稽问题写在表下方
- **银行流水导入**：CSV 编码嗅探（UTF-8/GB18030/UTF-16）、表头自动探测、
  列映射、三种收支表达方式、去重、**三层匹配**、批量生成凭证、与凭证双向关联
- **工资模块**：员工档案、**个税累计预扣预缴法**（7 级税率表）、
  劳务报酬按次预扣、社保公积金（基数上下限可配置）、
  计提 + 发放两张凭证、税率与社保方案全部数据驱动
- **发票档案**：专票/普票/电子专票/电子普票、进项销项、可抵扣判定、
  按「方向+代码+号码」判重；**一键生成凭证**（进项挂应付、销项挂应收），
  发票与凭证双向关联，汇总里单列「尚未入账张数」
- **差旅报销**：草稿 → 审批 → 记账的完整流转；驳回必须写明理由；
  选了费用类别自动带出默认科目；生成凭证时按明细逐条归集并拆分进项税额
- **附件**：SHA-256 内容寻址（天然去重）、路径穿越防护、归属关系入库、
  重复上传幂等、文件实体丢失检测、孤儿附件报告、凭证附件覆盖审计
- **期末结转**：结转损益（收入/费用 → 本年利润）、12 月自动结转本年利润到未分配利润；
  **结转分录继承辅助核算**（否则要求部门的费用科目过不了账）；结账前 6 项体检，
  阻断项不放过、提示项不误伤
- **现金流量表**：直接法 + 按**对方科目 + 现金方向**归类（销项税随货款流入算销售收款，
  向税局缴税才算支付的税费）；无法归类的分录**列出来**而不是静默丢弃；
  另用科目余额交叉验证期末现金
- **桌面界面**：首页概览（会计恒等式 + 待办）、**凭证录入**（科目/往来选择器、
  实时借贷平衡、双击填差额、保存草稿 / 红字冲销）、账期管理
  （预览 → 体检 → 结账 → 反结账）、5 张报表统一下钻、明细账、账龄分析、
  往来对账单、银行余额调节表、多栏式明细账、凭证汇总表、**AI 会计（对话式）**、
  设置与备份、建账向导；
  **打印 / 另存为 PDF**；深色模式；金额等宽右对齐、负数用括号（会计惯例）
- **提示条**：**全部自动收起**，区别只在停留时间 —— 信息类
  （success / info）**3 秒**，问题类（warn / error）**5 秒**
  （错误里常带 detail：体检没过的那几项、勾稽差额，要多留一点时间读）。
  认不出的 kind 按问题类算。两个时长是常量，见
  `desktop/frontend/src/lib/api.js` 的 `TOAST_MS_INFO` / `TOAST_MS_ISSUE`
- **界面上的文字一律可以用鼠标选中、可以复制**：
  - 拖选 / 双击选词 / 三击选段都正常，报表数字、凭证号、报错原文
    都能直接拷去 Excel 或聊天窗口；
  - 键盘 `Cmd+C` / `Ctrl+C`（Wails 的应用菜单里挂了标准 Edit → Copy）；
  - 右键：**有选中文字或光标在输入框里才弹系统菜单**，空白处右键不弹 ——
    不会冒出「重新载入」这种东西；
  - 三处任意一处坏掉，用户看到的现象都是同一句「这软件不能复制」，
    所以都由测试钉住：样式表查 `user-select:text`（见
    `desktop/frontend_assets_test.go`），右键菜单开关查启动选项
    （见 `desktop/appoptions_test.go`）
- **建账向导**：
  - **账套默认保存到 `<用户家目录>/.mini-account/dataDB/`**，三个平台完全一致
    （附件在同级 `.files/`，备份时整个 `dataDB` 拷走即可）。用户**一个字都不用填**
    就能建账；目录不存在会自动建出来。不放在程序旁边：`.app` / `.exe` 可能被拖进
    `/Applications`、被重装覆盖、或者从只读位置运行 —— 那样账套会跟着丢
  - **文件名一律英文**：单位名称里的汉字转成拼音，
    「杭州云帆软件有限公司」→ `hang-zhou-yun-fan-ruan-jian-you-xian-gong-si.db`。
    账套要在三种系统、备份包、U 盘、网盘之间搬，中文名在这些环节里
    出问题的概率不低（编码、归一化、命令行、别人的脚本），而用户看不出问题出在哪。
    留空或全是标点时兜底成 `book.db`；重名自动加序号（`book-2.db`），
    免得第二本账盖在第一本上。多音字按最常用读音取（重庆 → `zhong-qing`），
    文件名只要稳定可读就够了，看不顺眼可以直接改
  - **账套目录是隐藏目录，所以界面上给了出路**（`desktop/dialogs.go`）：
    建账页有「选择目录…」调起系统目录选择框、「打开目录」在
    Finder / 资源管理器里定位过去；打开账套那边有「浏览…」直接挑 dataDB 里的 `.db`。
    藏起来却不给入口才是问题，藏起来但一键可达是可以接受的
  - 默认纳税人身份是**小规模纳税人**（面向小微企业）。这只是一个**表单默认值**，
    点一下就改；程序**绝不**按销售额自动推导身份 —— 身份由税务登记决定
  - 单位名称里的 `/` `\` `:` 等绝不会进文件名，免得「张三/李四公司」
    把账套建到别的目录去
- **没有账套时，左侧菜单一律置灰、也切不过去**，并写明「建账之后这里的功能才会解锁」。
  「点得动但进去是空的 / 报错」比「点不动」糟糕得多 —— 用户会以为软件坏了，
  而不是以为自己还没建账。路由守卫同时挡住地址栏、书签与代码里的 `push`
- **凭证三态**：草稿（不占号、可改可删）→ 已记账（占号、进总账、只能红字冲销）
  → 已冲销。**差额绝不自动抹平**，但双击金额格可一键填入差额。
  界面上**没有**「保存并记账」：录完只是草稿，过账要等到账期结算。
  这条规则由测试守着（编辑器里出现这个按钮、或绑定层多出
  `SaveAndPost` / `PostVoucher`，测试就红）
- **工资**：员工档案（标准月工资、社保/公积金基数、专项附加扣除、部门、
  工资费用科目）、工资单（草稿 → 生成凭证，产出计提与发放两张**草稿**凭证）、
  个税参数页。标准值存档案、逐月可变的在工资单上填
- **部门档案**：辅助核算四维里唯一需要主数据的一维；建账时种入「管理部门」，
  否则第一次记费用就会撞上「缺少必需的辅助核算」而账套里一个可选部门都没有
- **Excel 导出**：走 Go 侧直接取数写 xlsx（金额写成**数值**，可在 Excel 里求和），
  默认文件名带单位名与期间
- **AI 辅助记账**：
  - 契约层严格解析（拒绝未知字段、重复键、小数金额、字符串金额）
  - **14 条护栏**逐条拦截（幻觉科目、汇总科目、借贷不平、辅助核算缺失/类型不符、期间越界…）
  - **绝不自动调平**：差额暴露给人，而不是用尾差科目抹平
  - 三层兜底：用户规则 → **历史同类凭证检索** → 模型推理
  - **AI Agent**：三个只读工具（搜科目 / 搜往来单位 / 检索历史凭证），
    模型可自行决定还要看什么，最多 3 轮；有副作用的工具一概不提供
  - **不提供批量记账**：曾经有一个「把没记账的流水/发票交给它跑一遍」的
    批量入口，已经删掉。理由是它与对话式会计重复，而且批量跑出来的
    几十条草稿仍需逐条核对 —— 省下的那点点击，抵不过「一条条看」这件事本身
  - **对话式会计**：页面上只有**一个业务描述输入框**。用大白话描述一笔业务，
    缺什么由它问 —— 追问是一个阻塞式工具（`ask_user`），
    选项带「这个选择的后果」，推荐的那个放第一个并标「（推荐）」，
    最多问 3 轮；问够了才出凭证。信息能查的绝不问人
    （科目、往来单位、上次同样的怎么记的，它自己查）
  - 会计版提示词与单次任务版**共用同一份硬边界与输出格式**，
    只多一节「与用户对话」—— 两套各写一份的话，改一处忘一处，护栏就有了缝
  - 隐私：本地模型不脱敏；云端自动遮账号与统一社会信用代码
  - 审计留痕：模型原话、结构化提议、护栏完整失败明细、token 数
  - AI 产物一律先是**草稿**，制单人签的始终是自然人

## 为什么这样设计

领域层解决的是 Frappe Books 里真实存在的、会让中国会计**算错账**的问题：

| 问题（Frappe Books） | 本工程的做法 |
| --- | --- |
| 金额存 TEXT，聚合时 `cast(as real)` 退回浮点 | `money.Money` = `int64` 分，全链路无浮点 |
| 退货靠写入**负数金额**，各报表对负数的处理还不一致 | 金额永远非负；冲销用**借贷互换**（`Posting.Reverse`） |
| 会计日期存成「本地日期的 UTC 午夜」，日期筛选退化为**字符串比较**，`toDate` 当天被静默漏掉 | `calendar.Date` 只有 Y/M/D，比较是数值比较，不存在时区漂移 |
| 科目**没有编码字段**，编码被拼进科目名称字符串 | `account.Code` 独立字段，4-2-2-2 纯数字，可排序可前缀匹配 |
| 科目**没有余额方向**，备抵科目（累计折旧/累计摊销）余额符号错误 | `Account.BalanceDir` 显式字段 |
| 根类型只有 5 类，**没有成本类**，生产成本被并入费用 → 资产负债表存货算错 | `RootType` 六类，含 `cost` |
| 只校验「借贷相等」，可以记到**汇总科目** | 过账时强制校验科目是明细科目且已启用 |
| 辅助核算只有一维 `party` | 四维（往来/员工/部门/项目），且按科目声明**强制填写** |
| 无会计期间、不能结账 | `period.Calendar` 状态机 + 顺序结账 / 逆序反结账 |
| 冲销不产生真实凭证（只是两行被隐藏的总账），报表漏写过滤就少算 | **红字凭证模型**：冲销是一张有编号的真实凭证，报表汇总全部分录自然抵消 |
| 凭证号是**全局计数器**，读-改-写有竞态，且不按期间分段 | 按「期间 + 凭证字」分配 + 部分唯一索引兜底 |
| `makeRoundOffEntry` **无上限**自动调平，掩盖分录错误 | `EnsureBalance` 只在限额内调尾差，超额报错 |
| 过账**没有事务**，逐条 insert，中途失败留下半张凭证 | 计划：一次过账一个事务（见 `docs/02` §5.1） |

## 纳税人身份：两套概念，分别保存

⚠️ **小微企业 ≠ 增值税小规模纳税人**，两者依据不同、用途不同、互不派生：

| | 企业规模类型 | 增值税纳税人身份 |
| --- | --- | --- |
| 依据 | 《中小企业划型标准规定》 | 《增值税法》 |
| 判定 | 营业收入 + 从业人员 | 年应征增值税销售额是否超 500 万元 |
| 用途 | 小型微利企业**所得税**优惠 | 计税方法、**能否抵扣进项** |
| 取值 | 微型 / 小型 / 中型 / 大型 | 一般纳税人 / 小规模纳税人 |

小微企业**可以自愿登记为一般纳税人**；年销售额未超 500 万元通常按小规模
纳税，但登记为一般纳税人同样合法。用「是不是小微」去推断「能不能抵扣进项」
是这类软件最常见的算错税原因，所以两套身份在建账时**分别指定**：

```bash
miniaccount init --db book.db --name "某某有限公司" --vat general --scale small
```

增值税税率政策是**带生效期的数据**，不是代码常量：

```bash
miniaccount vat                                     # 列出全部政策（含政策依据）
miniaccount vat --rate --status small_scale --category goods --on 2026-06-01
miniaccount vat --deduct --voucher special_invoice --tax 1300
miniaccount vat --ref                               # 凭证类型 / 不得抵扣原因
```

- **1% 优惠带截止日**（2027-12-31），到期自动回落到 3%，无需改代码
- **小规模销售/出租不动产、转让土地使用权不自动套用 1%**，按 3% 走单独规则
- **法定税率与实际优惠税率分开存**；计税方法（一般/简易/免税/零税率/不征税）单独存
- **进项抵扣**按「身份 → 计税方法 → 凭证类型 → 用途 → 长期资产 500 万」顺序判定，
  并区分「不予抵扣（计入成本）」与「进项税额转出」

## 操作日志

每一次影响账簿的操作都会记进**独立的**日志数据库（，
按 100MB 分片），可查、可校验、可导出：

```sh
miniaccount log                      # 最近 50 条
miniaccount log --actor 李会计 --from 2025-03-01 --to 2025-03-31
miniaccount log --action voucher.post --failed
miniaccount log --action all         # 列出全部操作种类
miniaccount log --verify             # 校验哈希链：日志有没有被改动过
miniaccount log --category read       # 只看「查看」类（谁看了哪张报表）
miniaccount log --record-views on    # 开关：是否记录查看操作（默认关）
miniaccount log --export 日志.csv     # 导出给审计（Excel 直接打开）
```

日志分三类：**业务操作**（默认只看这个）、**查看**（默认不记，打开开关才记）、
系统事件。查看类做了 60 秒去重 —— 不然界面刷新一次就写一条。

界面上有「操作日志」页，同样支持按操作人/时间/操作种类/结果/关键字组合查询。

★ 设计与依据（财政部《企业会计信息化工作规范》的完整性/安全性/可查询性三条）
见 《02-Go重写方案》 §40。

## 构建与版本

```sh
./build.sh              # 用代码里的版本号构建
./build.sh 0.2.0-rc3    # 指定版本号
```

产物在 `dist/`：`miniaccount-darwin-arm64`（命令行）与
`小账本.app` / `小账本-darwin-arm64`（桌面）。

```sh
miniaccount version      # 版本号 + 构建时间
```

★ 报告问题时请带上这一行输出 —— 版本号对不上，看到的输出可能是旧程序产生的。

★★ **改完界面一定要 `./build.sh`（或至少 `cd desktop/frontend && npm run build`）。**
`wails build` 只是在编译时把 `desktop/frontend/dist` 嵌进二进制，
它不会替你把 `src` 重新打一遍 —— 不重建的话，`src` 里的改动
在用户双击的那个 `.app` 里根本不存在。

★★★ **验证平台构建别用裸 `go build`，会给假绿灯。**

平台前端是由 **`production` 构建标签**门控的 —— Wails 的
`internal/app/app_production.go` 才是 `//go:build production` 那个
import 平台前端的文件，`wails build` 默认带上它，裸跑 `go build` 不带。
于是 `GOOS=windows go build ./desktop` **根本编不到 Windows 前端**，
报「通过」但什么都没验。

我们就这样漏过一次：`go.mod` 把 `go-webview2` 抬到了 v1.0.22，
而 v1.0.22 改了 `MessageCallback` 的签名（`func(string)` →
`func(string, *ICoreWebView2, *ICoreWebView2WebMessageReceivedEventArgs)`），
Wails v2.10.2 只兼容 v1.0.19 —— 本地一路绿灯，CI 上 Windows 直接编译失败。

本地能做的检查：

```sh
# Windows：纯 Go，交叉编译可行（标签要和 wails build 一致）
GOOS=windows GOARCH=amd64 go build \
  -tags production,native_webview2loader ./desktop
```

macOS 与 Linux 的界面版**只能在对应系统上验**：macOS 要用 `wails build`
（裸 `go build` 会缺 Wails 的链接参数），Linux 要 cgo + GTK/WebKit 头文件，
从别的系统交叉编译不了。所以改 `go.mod` 里的依赖版本之后，
**用 `./build.sh` 走一遍，或者直接打标签让 CI 跑**。

### 发布：三个平台一起出包

**标签就是版本号的唯一来源。** 不用改任何代码 —— CI 拿到标签之后，
会把版本号同时注入 `service.AppVersion`（`miniaccount version`、
备份清单、操作日志读它）和 `wails.json` 的 `productVersion`
（macOS 的 `CFBundleShortVersionString`、Windows exe 的版本信息）。

一条命令发版：

```sh
./release.sh 0.2.0        # 正式版，会拿到 Releases 页面的 Latest 标记
./release.sh 0.2.0-rc1    # 预发布，标 pre-release，不抢 Latest
```

它做的事：检查版本号形状 → 工作区干净 → 在 main 上且与远端一致 →
标签没被用过 → 确认后打**附注标签**并推送。推上去就触发 CI。

想跳过脚本手动来也行，效果一样：

```sh
git tag -a v0.2.0 -m "小账本 0.2.0"
git push origin v0.2.0
```

跑完之后 Release 页面上有三个压缩包：

| 平台 | 文件 | 里面是什么 |
| --- | --- | --- |
| macOS（Apple 芯片 / Intel 通用） | `miniaccount-<版本>-macos-universal.zip` | `小账本.app` + `miniaccount` |
| Windows 10/11 64 位 | `miniaccount-<版本>-windows-amd64.zip` | `小账本.exe` + `miniaccount.exe` |
| Linux 64 位 | `miniaccount-<版本>-linux-amd64.tar.gz` | `小账本` + `miniaccount` + 说明 |

#### 标签规则

- 一律 `v` 开头：`v0.2.0`。CI 去掉 `v` 当版本号，产物文件名里用的是去掉之后的。
- **带连字符就是预发布**：`v0.2.0-rc1`、`v1.0.0-beta.2`。
  CI 会显式标成 pre-release —— 不这样的话它会被当成正式版，
  还会顶掉 Releases 页面的「Latest」，来下载的人第一眼看到个 rc 却以为稳定。
- 版本号一次只前进，**推上去就不再动**。要重发同一个版本，先删标签再重打；
  代码没变只是想重跑 CI 的话不用删标签，去 Actions 点 Re-run failed jobs 就行。

#### 几个容易踩的地方

- **别用 `git push --follow-tags`** 顺手推标签 —— 那会把本地攒的所有标签
  一起推上去，每个都触发一次三平台构建。
- **发版前先 `git push origin main`**。标签指向本地提交，而 CI 是按标签拉代码的；
  本地领先远端时，标签会指向一个远端还不存在的提交，构建直接失败。
  `release.sh` 会挡住这种情况。
- **本地构建的版本号**：`./build.sh` 不传参数时沿用 `service.AppVersion`
  （仓库里是 `0.2.0-rc2`，也就是「下一个版本的开发号」）。正式发布时 CI 用
  标签号覆盖它。所以看到 `-rc2` / `-dev` 结尾的就是本地构建，不是发布版。
- 想验证三平台编不编得过又不想占版本号，去 Actions 页面点 Run workflow：
  它发一个带日期的 `dev-<日期>-<构建号>` Release，不会碰正式版本。

#### 两个已知的平台坑

- Linux 用 WebKitGTK **4.1**（Ubuntu 24.04 起没有 4.0 了）。在较老的发行版上
  可能报 GLIBC 版本不够 —— 包内说明里写了这种情况改用命令行版（纯 Go、无依赖）。
- macOS 的 `.app` 必须用 `ditto` 打包，不能用 `zip -r`：后者会丢掉包内的
  符号链接与权限位，解压出来打不开。

## 备份与恢复

```sh
miniaccount backup  --db book.db --out book.mabak   # 数据库快照 + 附件打成一个文件
miniaccount inspect book.mabak                      # 先看清单，不恢复
miniaccount restore --from book.mabak --db book.db  # 恢复
```

恢复会先把原账套整体挪到 `.restore-stash-<时间戳>/` 并在输出里报出路径；
恢复出错自动回滚。**没有旧账套时不会建空目录** —— 空目录不是退路。

## 第一版边界（用之前请先看这几条）

详见 《02-Go重写方案》 §32。

1. **工资模块必须先配社保方案** —— 本工程刻意不预置任何费率
   （预置一组看着像真的数字会被直接当真使用，而算错了不会报错）。
   用 `miniaccount schemes --template 方案.json` 生成空表，按当地社保局标准填写后 `--import` 导回。
2. **个税建议从 1 月起连续建单** —— 年中启用时减除费用按任职月份算、
   累计收入却只有建过单的月份，个税会少扣（界面有 ⚠ 提示，但暂不支持补录历史累计数）。
3. **小规模纳税人**用「价税合计全额计入费用」记账，不能用进项抵扣专栏
   （程序会明确拒绝并说明正确做法）。
4. **红字发票 / 退货**需人工在台账上备注；**可抵扣凭证只认专票**
   （通行费、火车票机票、农产品收购发票需人工调整）。
5. **税率与抵扣范围已按 2026 年现行文件落到「数据」里**，仍建议发布前复核 ——
   科目表结构依据的财会〔2016〕22号 是会计处理规定，风险较低；
   税率清单属实体法内容，且**政策会变**（政策表版本 2026.2，
   1% 优惠截止 2027-12-31，到期后程序自动回落到 3%）。
6. **出口业务首版只到「问得清」，不到「做得完」** ——
   查「小规模 + 出口 + 零税率」会明确回答「你的身份不适用零税率，
   出口适用免税、不退税，进项不得抵扣也不得退税」，并说明存在征税例外；
   但**出口发票、退免税申报表不在首版范围**。
   零税率只适用于采用一般计税的一般纳税人，**不放宽给小规模纳税人**。

§28 列的三个小缺口已在 §29 收掉（日记账「对方科目」、
