# 项目分析

## 定位与范围

本项目是面向中国小微企业的本地财务记账软件，提供桌面应用与命令行。以下是基于仓库入口、目录及核心代码的初步静态分析，不代表完整审计或已验证全部功能。

## 技术与架构

- Go 1.25、Wails v2、SQLite、Vue 3、Vite 和 Tailwind CSS。
- `desktop/frontend` 是 Vue 界面，通过 Wails 绑定调用 `desktop`，由 `internal/service` 编排业务，`internal/domain` 承载领域规则，`internal/store/sqlite` 负责存储与事务。
- `cmd/miniaccount` 提供命令行入口；附件、备份、导出和 AI 适配分别位于 `internal/attachment`、`internal/backup`、`internal/export` 和 `internal/ai`。
- 账套存储在 SQLite 文件中；迁移脚本位于 `internal/store/sqlite/migrations/`，当前包含 0001 至 0015。SQLite 连接池限制为单连接，写事务采用 immediate 锁、启用外键及 WAL。

## 业务能力

- 建账、科目和辅助核算、凭证、账簿与财务报表。
- 银行流水、发票、报销、工资、固定资产折旧和费用摊销。
- 期间管理、损益结转、账龄、往来对账和银行余额调节。
- 税务计算、申报台账、审计底稿与证据链、审计文书。
- 附件、备份恢复、Excel 导出和 AI 辅助记账。

以上能力依据 README、路由和目录归纳，具体可用性须按实际场景验证。税务计算表和审计文书不应视为自动申报或可直接签发的正式文件。

## 关键财务约束

1. 金额类型 `money.Money` 使用以分为单位的 `int64`，金额计算和舍入应沿用现有实现。
2. 过账引擎校验借贷平衡、有效科目、分录方向、摘要及辅助核算等规则；冲销生成真实凭证，采用借贷互换。
3. 正常业务先保存草稿；结账时在同一事务内过账本期草稿、结转损益并关闭期间。红字冲销和反结账具有不同处理要求。
4. 结账要求期间顺序，反结账要求逆序。报表与派生计算依赖账簿数据，修改必须评估历史账期和下游报表影响。
5. 附件按内容哈希管理；备份恢复涉及数据库和附件一致性，不能只考虑数据库文件。
6. AI 结果必须经过现有规则校验并保持人工审核与草稿边界，不能信任模型直接写账。

## 后续开发重点

- 先梳理业务场景、输入输出、会计口径和关联数据，特别关注金额精度、借贷平衡、事务、历史数据、审计追溯及权限/隐私。
- 涉及数据库时考虑已有账套的迁移、约束和回滚；涉及 Wails 时同时检查 Go 绑定、前端 API 和真实运行时契约。
- 涉税逻辑需要确认政策适用时间和地区，不能仅凭当前默认参数推断合规性。
